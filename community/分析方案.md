# 社区信源结构化分析方案

## 目标

建立一套与官网信源看板分离的社区信源分析链路。第一阶段回答“哪些社区能稳定访问、能抓到什么内容、内容是否与 K12 升学相关、哪些来源值得继续投入”，不直接回答政策真伪，也不把社区内容写入官方动态。

## 数据层次

### 信源层

每个社区保存：社区名称、入口 URL、地区、来源类型、覆盖学段、公开访问条件、登录/反爬限制和备注。

### 页面层

每次巡检保存：抓取时间、入口 URL、HTTP 状态、访问状态、页面字符数、内部链接数、是否 404、是否登录墙、是否反爬、错误信息和正文预览。

### 内容层

每条帖子或文章保存：标题、原始链接、来源社区、来源栏目、发布时间、抓取时间、作者显示名、正文、地区、学校、学段和事件类型。

### 分析层

每条内容增加：排除词命中、推荐词标签、地域置信度、内容类型、事实状态和质量备注。推荐词只用于标签和排序，不能单独作为保留条件。

## 分阶段执行

### 阶段一：入口盘点

输入：`sources/论坛与社区信源.md`

输出：入口巡检报告，回答页面是否可访问、是否有列表链接、是否需要专用解析。此阶段不生成帖子库。

### 阶段二：列表页采集

只对阶段一确认可访问的入口采集公开列表页，优先保存标题、链接、时间和栏目。每个社区先限定页数和条数，避免无限遍历。

### 阶段三：详情页采集

从列表页选择有限数量的详情页，保存正文和页面元数据。遇到登录、验证码、付费或反爬时停止该来源，不做绕过。

### 阶段四：规范化与去重

按原始 URL、标题、发布时间和正文指纹去重；统一日期、地区、学校名称和来源名称。原始记录不覆盖，只在规范化层标记重复和修订。

### 阶段五：质量分析

从五个维度评分：

| 维度 | 判断内容 |
|---|---|
| 可访问性 | 是否能稳定打开，是否需要登录或容易触发限制 |
| 相关性 | 是否持续出现招生、入学、学校和升学内容 |
| 地域清晰度 | 城市、区县和学校是否能明确识别 |
| 信息密度 | 有效帖子、正文和可追溯链接的比例 |
| 噪声与风险 | 广告、培训、房产、传闻和重复转载比例 |

### 阶段六：报告输出

最终报告分为四部分：

1. 入口可用性：成功、受限、失败和需要专用解析的入口。
2. 内容样本：各社区实际抓到的标题、时间、链接和正文摘要。
3. 来源质量：不同社区的内容价值、噪声、稳定性和风险。
4. 后续动作：继续抓取、改写解析器、人工参考或暂停接入。

## 明确不做

- 不把社区页面能打开等同于来源可信。
- 不把匿名传闻自动改写成确定性事实。
- 不把社区内容直接合并到官网信源、学校动态或官方 RSS。
- 不抓取私密群组，不绕过登录、验证码、会员和付费限制。
- 不在第一阶段追求“所有帖子全部抓完”。
