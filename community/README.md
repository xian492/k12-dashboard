# 社区信源采集与分析

这里存放论坛、家长社区、地方生活论坛及其他公开第三方信源的独立采集和分析工作。社区数据通过独立展示快照接入官网看板，但不并入官方信源数据和官方 RSS。

## 工作边界

只访问公开页面，不登录、不绕过验证码、付费墙、会员限制或反爬措施。社区内容用于发现线索和观察家长实际反馈，不能替代教育部门、考试院或学校的原始公告。

## 分析流程

### 1. 信源登记

维护来源名称、入口 URL、地区、来源类型、覆盖学段、公开访问条件和主要限制。

### 2. 入口巡检

判断入口是否可访问、是否返回有效正文、是否有内部列表链接、是否存在 404、登录墙、验证码或反爬。入口巡检不等于已经抓取帖子内容。

### 3. 内容抓取

对可访问入口抓取列表页和有限详情页，保存标题、原始链接、发布时间、作者显示名、正文、来源社区和抓取时间。原始响应与规范化记录分开保存。

### 4. 去噪与归类

先执行排除词过滤；推荐保留词只作为标签和排序参考，不作为唯一准入条件。为每条记录补充地区、学校、学段、事件类型和信息状态。

### 5. 质量分析

区分官方转述、家长经验、匿名传闻、商业推广和纯导航页面；统计来源活跃度、内容相关性、地域清晰度、可重复抓取性和商业噪声比例。

### 6. 报告输出

报告分为入口可用性、内容样本、来源质量和后续接入建议，不把“页面能打开”直接写成“信源可信”。

## 与官网看板的关系

官网学校和教育部门信源仍由项目根目录的 `tools/build.py`、`docs/index.html`、`docs/feed.xml` 等链路负责。社区链路由 GitHub Actions 每 6 小时调用，社区内容只进入看板的独立社区视图，不进入官方动态和官方 RSS。

首期自动刷新最多访问 6 个北京社区入口页和 420 个详情页。社区刷新失败时保留上一份 `docs/community-data.json` 快照；社区视图显示最近成功状态，官方视图继续正常部署。
