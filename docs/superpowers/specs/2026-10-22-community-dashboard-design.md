# 官方与社区双信源看板设计

## 1. 目标

在现有北京 K12 官方信源看板中增加社区信源视图，并通过页面顶部下拉框切换两种视图。社区信源每 6 小时自动更新，但不与官方信源混合展示、不进入官方 RSS，也不改变官方数据的可信度口径。

首期只接入 `community/data/community_beijing_enriched.json` 中的北京社区有效结果。后续增加城市时，沿用同一数据结构和视图协议。

## 2. 非目标

- 不把社区内容写入官方 `docs/data.json` 的官方条目结构。
- 不把社区内容写入官方 `docs/feed.xml`。
- 不把社区帖子直接标记为政策事实或官方公告。
- 不在本阶段接入登录、付费、验证码或半封闭社群。
- 不在本阶段同时扩展上海、广州等城市。

## 3. 页面体验

现有页面顶部增加一个信源选择器：

```text
信源视图：[官方信源看板 ▼]
             官方信源看板
             社区信源看板
```

选择官方视图时，页面保持现有官方看板内容和布局。选择社区视图时，页面切换为社区专用内容区，并显示醒目的边界说明：

> 社区内容仅用于发现线索和观察家长反馈，未经教育部门、考试院或学校官方页面核验，不等同于官方信息。

社区视图包含：

- 最近一次社区采集成功时间；
- 当前展示记录数；
- 按学校阶段分组：小学（幼升小、小升初、中招）、中学（中考、初升高）、高中（高考及相关内容）；
- 学校阶段下按内容类型分组：政策与流程、学校动态、家长经验；
- 标题、原始社区链接、发布时间；
- 事件类型作为条目标签展示，不参与目录分组；
- 每条记录保留来源社区名称，便于回到原社区核对；
- 区县和学校候选；
- 核验状态，初期统一显示“待官方核验”。

社区视图不显示作者账号、用户资料、联系方式和群入口。

## 4. 数据边界

官方数据继续由 `tools/build.py` 生成：

```text
官方抓取 → docs/data.json → 官方视图
         → docs/feed.xml
```

社区数据单独经过以下链路：

```text
community_crawler.py
  → community_content_crawler.py
  → community_content_cleaner.py
  → community_content_enricher.py
  → community dashboard export
  → docs/community-data.json
  → 社区视图
```

`docs/community-data.json` 只保存前端需要的展示字段，不把完整正文和原始抓取快照复制进官网页面。完整数据继续保存在 `community/data/`，用于分析和复核。

## 4.1 首期自动更新入口与抓取上限

《论坛与社区信源》是信源登记表，不等于所有入口都进入定时自动抓取。首期自动更新只使用 `community/tools/community_crawler.py` 中的北京入口白名单。每轮任务先抓入口页，再从入口页发现同站公开链接，最后抓取不超过下表上限的详情页。

| 来源 | 自动入口 | 入口页 | 每轮详情页上限 | 当前试采候选量 | 自动处理方式 |
|---|---|---:|---:|---:|---|
| 北京小升初网 | 政策资讯 | 1 | 100 | 82 | 抓公开文章详情，排除登录、课程、资料和群推广页 |
| 水木社区·儿童教育 | ChildEducation | 1 | 50 | 20 | 抓公开帖子详情，保留北京升学相关内容 |
| 北京小升初信息网 | 北京小升初 | 1 | 120 | 112 | 抓文章详情，保留 URL 日期和原始链接 |
| 回龙观社区网 | 文化讨论区 | 1 | 50 | 110 | 首期只取前 50 个候选；详情页超时较多，失败不阻断任务 |
| 芍药居社区网 | 入学政策版 | 1 | 100 | 95 | 抓公开主题页，剥离论坛操作区和用户资料 |
| 北京小升初升学索引 | 首页 | 1 | 0 | 0 | 只巡检入口，不递归抓取；当前没有稳定内部内容链接 |

因此首期每轮最多访问 **6 个入口页 + 420 个详情页，共 426 个页面**。这是页面访问上限，不代表一定成功；实际展示数量还要经过状态过滤、排除词清洗、正文提取和有效性判断。

“当前试采候选量”来自本次 2026-10-22 的一次性巡检，不是自动任务的固定结果。自动任务每轮会按同样的入口和上限重新发现链接，并优先保留入口页当前暴露的候选；不会因为历史样本有 419 条就永久固定抓取这 419 条。

以下入口暂不进入首期自动任务：

- 北京小升初网的家长经验、家长社群和公众号矩阵：入口结构或访问条件不稳定，先保留人工参考；
- 邻友圈公开帖子示例：目前只有单帖 API 示例，没有稳定公开列表入口；
- 水木社区·学区房板：房产内容占主导，暂不纳入首期自动看板；
- 贴吧、知乎、妈妈网、小红书、抖音、微信群、QQ群和知识星球：存在登录、推荐流、社群或访问限制，不作为首期自动抓取入口；
- 其他城市入口：北京自动链路稳定后再单独增加，不与首期页面混合验收。

自动任务不抓取用户资料、私信、联系方式、群二维码和需要登录才能看到的内容。入口页成功但详情页失败时，保留入口状态和失败原因，不将失败页当作社区内容。

建议的展示记录结构：

```json
{
  "title": "2027北京小升初入学指南",
  "link": "https://www.xschu.com/zhengcezixun/86941.html",
  "source": "北京小升初网",
  "region": "北京",
  "district_candidates": ["海淀区", "西城区"],
  "school_candidates": [],
  "published_at": "2026-10-22",
  "content_type": "政策与流程",
  "stage": ["小升初"],
  "event_type": ["入学", "报名"],
  "verification_status": "待官方核验",
  "community_notice": true
}
```

## 5. 自动更新

沿用现有 `.github/workflows/build.yml` 的每 6 小时调度，但将社区采集作为独立阶段执行。推荐顺序：

1. 安装 Crawl4AI 和浏览器组件；
2. 创建社区临时输出目录；
3. 运行北京入口发现和详情页抓取；
4. 运行清洗、正文抽取和分析字段生成；
5. 只有在社区流水线达到最低成功条件时，才替换展示数据；
6. 官方抓取继续执行；
7. 将官方页面、社区展示 JSON 和状态元数据一起发布到 Pages。

社区最低成功条件：

- 入口脚本正常结束；
- 详情页结果文件存在且是合法 JSONL；
- 清洗和分析脚本正常结束；
- 有效记录数大于 0；
- 展示 JSON 能通过结构校验。

若社区流水线失败：

- 不覆盖仓库中已有的社区展示快照；
- 官方看板继续构建和部署；
- 社区视图显示上一次成功时间；
- 在状态字段中记录本轮失败原因。

## 6. 文件与模块

新增或调整范围限定在以下位置：

| 文件 | 作用 |
|---|---|
| `community/tools/community_dashboard_export.py` | 将 enriched 数据转换为前端展示 JSON |
| `docs/community-data.json` | Pages 使用的社区展示快照 |
| `tools/build.py` | 读取社区展示快照并生成双视图页面，不改变官方抓取逻辑 |
| `.github/workflows/build.yml` | 每 6 小时执行社区链路并传递失败状态 |
| `tests/test_build.py` | 测试视图切换、社区数据缺失和官方数据不受影响 |
| `community/tests/` | 测试社区导出字段和失败条件 |
| `community/README.md` | 更新自动更新和看板说明 |

社区原始数据、清洗数据和报告继续留在 `community/`，不搬入 `docs/`；`docs/` 只保留前端部署需要的最小展示快照。

## 7. 失败和安全边界

- 单个社区来源失败不影响其他社区来源。
- 所有来源仍只访问公开页面。
- 不绕过反爬、验证码、登录和访问限制。
- 社区内容在页面上始终保留原始链接。
- 社区摘要不自动生成确定性政策结论。
- 展示层不输出用户账号、联系方式和群信息。
- 社区导出数据不进入官方 RSS。

## 8. 测试与验收

自动化测试至少覆盖：

1. 社区 enriched 记录能正确转换为展示记录；
2. 缺少可分析记录时导出失败且不覆盖旧快照；
3. 页面包含官方/社区选择器；
4. 切换到社区视图时显示社区边界提示；
5. 官方视图仍包含原有市级、分区和学校结构；
6. 社区记录不出现在官方 RSS；
7. 社区采集失败时官方构建仍能完成；
8. 社区展示 JSON 不含完整正文、作者资料或群入口。

验收标准：

- 手动运行构建后可以在页面下拉切换两种视图；
- 社区视图能显示北京有效社区结果，并可点击回到原社区页面；
- 连续模拟社区失败后，官方视图仍可部署，社区视图保留旧快照；
- 每 6 小时的 GitHub Actions 任务不会因为单个社区来源失败而整体失败；
- 官方 `docs/feed.xml` 内容和结构不发生社区混入。
