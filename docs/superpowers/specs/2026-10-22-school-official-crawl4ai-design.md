# 学校官网 Crawl4AI 采集设计

## 1. 目标

为现有 K12 官方信源看板增加学校官网内容采集能力，优先解决当前大量学校只有官网链接、没有可展示动态的问题。

本阶段只处理学校官方官网，不处理论坛、家长社区、公众号或其他第三方信源。Crawl4AI 作为学校官网采集的主要执行引擎，现有官网目录继续作为学校元数据和导航入口。

验收目标：

- 能对现有学校目录中的官网进行批量可访问性和内容结构探测。
- 能从一批结构不同的学校官网中发现新闻、通知、招生或校园动态栏目。
- 能抽取标题、链接、发布日期和栏目，并分配到正确学校。
- 单个学校失败不影响其他学校、官方区级信源和页面发布。
- 结果可进入现有学校动态和 RSS，但不生成没有真实内容的占位条目。

## 2. 当前上下文与边界

当前项目使用 `tools/build.py` 完成官方信源抓取和 `docs/` 页面生成，并由 GitHub Actions 每 6 小时运行。学校目录中约有 149 个学校入口，但只有一部分学校在 `SCHOOL_SPECS` 中配置了具体列表页和正则规则；其余学校通常只有官网链接，或暂时使用区政府、区教委的官方补充信息。

本设计保留现有官方信源逻辑、区级政策逻辑、学校目录和页面布局，不把 Crawl4AI 用于社区信源，也不要求一次性覆盖所有学校。

明确不做：

- 不抓取需要登录、验证码或绕过访问控制的内容。
- 不无限制遍历学校域名，不抓取站外文章、用户评论或个人资料。
- 不默认使用 LLM 生成或改写学校新闻。
- 不把学校官网内容与社区线索混合。
- 不因无法抓取而生成“暂无动态”之类的虚假内容。

## 3. 方案选择

### 方案 A：全部继续使用手写正则

优点是依赖少、运行快；缺点是每种学校 CMS 都需要单独维护规则，无法解决只有官网入口的学校，且页面改版容易失效。

### 方案 B：全部使用 Crawl4AI 自动提取

优点是能处理 JS 渲染、等待加载和复杂交互；缺点是运行成本高，通用规则对学校官网的栏目语义和日期识别仍可能不稳定，完全自动发现容易误抓导航和广告。

### 方案 C：Crawl4AI 主引擎 + 配置化规则 + 旧规则兜底（推荐）

Crawl4AI 负责浏览器加载、JS 执行、候选链接发现和结构化提取；每个学校只配置必要的入口、允许域名、候选关键词和可选 CSS 选择器。现有 `SCHOOL_SPECS` 规则在迁移期间保留为兜底。这样可以先覆盖“只有官网链接”的学校，同时保留已验证规则的稳定性。

采用方案 C。

## 4. 总体架构

新增独立的学校官网采集模块，不把浏览器控制逻辑继续堆入 `tools/build.py`：

```text
学校目录 / 官网入口
        ↓
官网探测器
        ↓
候选栏目发现
        ↓
Crawl4AI 列表页抽取
        ↓
标准化、过滤、去重、学校归属
        ↓
学校动态数据
        ├── 现有看板
        └── 现有 RSS
```

建议的模块边界：

```text
tools/school_crawler/
  sources.py       # 学校入口、允许域名和采集配置
  browser.py       # Crawl4AI 生命周期和通用运行参数
  discover.py      # 首页和栏目候选发现
  extract.py       # 列表页结构化抽取
  normalize.py     # URL、标题、日期和学校字段标准化
  filter.py        # 导航、广告、无效内容过滤
  run.py           # 批量运行、并发限制、结果汇总
```

如果实现阶段发现现有构建函数必须复用，允许从 `tools/build.py` 调用 `run.py` 的公共入口，但 Crawl4AI 的具体逻辑仍留在独立模块。

## 5. 采集流程

### 5.1 官网探测

每个学校首次接入或配置失效时：

1. 打开官网入口，使用 Chromium 无头模式。
2. 等待 `domcontentloaded`，必要时按配置等待某个 CSS 选择器或固定短延迟。
3. 提取可见文本和同域链接。
4. 根据 URL 和链接文本识别候选栏目，例如“新闻、通知、公告、招生、校园动态、学校新闻、信息公开”。
5. 排除首页、学校简介、联系我们、友情链接、备案、登录、招聘和明显的非内容页面。
6. 每校最多保留 3～5 个候选栏目，并记录探测状态。

探测结果不直接展示，先写入健康记录，包含最终 URL、HTTP 状态、页面类型、候选栏目、最近可见日期、错误原因和探测时间。

### 5.2 列表页抽取

对候选栏目页提取最近内容。优先顺序：

1. 学校配置的 CSS/XPath 选择器。
2. Crawl4AI 的 `JsonCssExtractionStrategy`，抽取重复列表项中的标题、链接和日期。
3. 通用链接启发式：链接文本长度、URL 路径、日期邻近文本和栏目关键词。
4. 现有 `SCHOOL_SPECS` 正则规则作为迁移期兜底。

不使用 LLM 作为默认抽取器；只有人工确认某个站点无法用 DOM 规则稳定处理时，才单独评估 LLM 方案及其凭据、成本和可复现性。

### 5.3 内容标准化

每条学校动态至少包含：

```json
{
  "school": "人大附中",
  "district": "海淀区",
  "category": "通知公告",
  "title": "...",
  "url": "https://...",
  "published_at": "2026-10-22",
  "date_source": "page|url|crawl",
  "source_homepage": "https://...",
  "source_method": "crawl4ai",
  "content_hash": "..."
}
```

发布日期优先取页面明确日期，其次取 URL 中可识别日期；如果只有抓取日期，必须标记 `date_source=crawl`，不能伪装成发布日期。

URL 需要绝对化、去除跟踪参数并保持可访问的原始链接。标题需要去除空白、HTML 实体和站点重复前缀。相同 URL 或标题归一化后相同的内容去重。

### 5.4 归属和过滤

学校归属只使用当前学校配置和明确的官网域名，不根据新闻正文中的同名学校自动跨校归属。每条内容必须归属于一个已登记学校，否则进入探测日志，不进入学校动态。

过滤以下内容：

- 首页导航、学校简介、联系我们、友情链接和备案信息。
- 招聘、采购、预算、决算、审计等不属于学校动态的行政页面，除非后续明确需要。
- 空标题、无有效链接、明显重复模板内容。
- 外部推广、培训、课程和广告链接。

## 6. 数据与看板集成

学校官网采集结果沿用现有学校动态数据结构，保留来源方式字段，便于区分 `crawl4ai`、旧版规则和区级官方补充。

当前页面行为保持不变：

- 有真实动态时展示标题、日期和链接。
- 没有真实动态时只展示学校官网入口。
- 不用通用区级新闻替代学校动态。
- RSS 只加入通过学校归属和有效内容过滤的条目。

建议同时生成独立的健康数据，用于排查学校官网失效，但健康数据不直接显示为学校动态：

```text
school_id
homepage
last_probe_at
last_success_at
status
candidate_sections
items_found
consecutive_failures
error
```

## 7. 运行和部署

本地使用项目 `.venv` 中的 Crawl4AI。GitHub Actions 使用 Python 3.12，安装 Crawl4AI 后运行 `crawl4ai-setup` 准备浏览器。浏览器缓存应接入 Actions 缓存，避免每 6 小时重复下载。

运行约束：

- 首次探测阶段低并发，建议 2～4 个学校并行。
- 单校设置独立超时和异常捕获。
- 列表页只抓最近有限条数，不进行全站深度爬取。
- 站点失败时记录失败并继续，不让整个构建失败。
- 先对 5～10 所学校运行，稳定后再扩大到全目录。

GitHub Actions 仍然负责生成 `docs/` 和发布 Pages；Crawl4AI 只作为构建过程中的采集依赖，不改变 Pages 的部署方式。

## 8. 分阶段实施

### 阶段 1：小样本验证

选择已有规则和只有官网入口的学校各若干所，验证：

- 官网可访问性。
- JS 页面加载。
- 栏目发现。
- 标题、日期、链接抽取。
- 现有正则结果与 Crawl4AI 结果的一致性。

### 阶段 2：建立学校采集配置

将探测到的稳定栏目写入配置，保留站点特例；把明确失败、需要登录或结构无法稳定识别的学校标记为不可自动采集，并保留人工官网入口。

### 阶段 3：接入定时构建

接入 GitHub Actions，加入 Python 3.12、依赖安装、浏览器缓存、运行日志和健康数据。连续验证至少 3 次定时构建后，再扩大学校覆盖范围。

### 阶段 4：逐步迁移旧规则

对于 Crawl4AI 结果连续稳定的学校，逐步减少对应的手写正则；保留旧规则作为明确的回退路径，直到新采集方式经过一段时间的线上验证。

## 9. 测试与验收

单元测试覆盖：

- URL 绝对化和跟踪参数清理。
- 日期识别与 `date_source` 标记。
- 标题归一化和重复内容去重。
- 导航、广告和无效链接过滤。
- 学校归属和未知学校拒绝规则。

集成测试使用固定 HTML 快照或本地测试页面，不依赖每次都访问真实学校官网。至少准备：静态列表页、JS 延迟列表页、相对链接、无日期列表、分页页面和失败页面。

上线前验收：

- 目标样本学校至少连续成功抓取 3 次。
- 抓取结果没有把首页导航误当动态。
- 一个学校超时不会阻塞构建。
- 页面和 RSS 不出现占位动态。
- GitHub Actions 可以从干净 runner 完成安装、抓取和发布。
