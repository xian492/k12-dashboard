# 设计方案：信息置信度与时效性（v1，已对齐研究综述）

> 状态：v1，2026-10-23。文献依据见 `research-信息可信度与时效性验证.md`（40 条参考，一手来源已核验），本文件是落到本仓库的机制设计。
> 核心命题：**如何保证聚合信息的真实性与时效性**，并以用户可理解的方式展示（"搜到 xxx 条，每条来源是哪、置信度多少"）。

## 0. 设计约束

- 构建链路是纯 Python 标准库、GitHub Actions 每 6 小时一次，**不能引入 NLP 模型/外部 API**
- 展示端是纯静态 HTML，置信度逻辑必须**可离线计算、可解释**
- 已有资产：149 校名单（天然实体词典）、`event_type`/`stage`/`content_type` 分类字段、`needs_official_verification` 标记、`school-crawler-health.json` 抓取健康度、每条 item 的 `date`/`link`/`src`

## 1. 三层模型

```
信源信任权重 (source tier)     —— 静态，人工分级 + 历史表现修正
        ↓
条目基础置信度 (item base)     —— 来源权重 + 抽取质量
        ↓
验证后置信度 (verified)        —— 交叉验证 ±、时效性 ×
```

### 1.1 信源信任权重（人工分级，不自动学习）

| 层级 | 信源 | 权重 | 理由 |
|---|---|---|---|
| T0 | 教育部、市教委、yjrx 入学平台 | 1.0 | 政策原始出处，事实定义者 |
| T1 | 区政府/区教委门户 | 0.9 | 官方二级出处 |
| T2 | 学校官网（自有域名） | 0.8 | 本校事务的权威源，但排版/更新不规范 |
| T3 | 官方托管建站平台（bjhdedu.cn 等） | 0.8 | 同为官方发布，仅托管差异 |
| T4 | 垂直媒体（北京小升初网等） | 0.5 | 转述官方 + 自采混合，无原始证据 |
| T5 | 家长社区/论坛 | 0.3 | 经验信息，真伪未验 |

设计要点：
- **权重挂在 source_id 上**（新增 `tools/source_tiers.py` 一张静态表），构建时注入每条 item 的 `tier` 字段
- T4/T5 不因"说得对"而自动升权（避免自我强化循环）；只在**官方确证事件**里记录"T4 源 X 次被证实、Y 次被证伪"作为展示参考，不反馈进分数
- 拉取健康度（已有 school-crawler-health.json）单独展示，不混入信任权重——"连不上"和"不可信"是两个维度

### 1.2 条目基础置信度

```
base = tier_weight × extraction_quality
```

`extraction_quality`：日期是否可抽得（0.9）/ 无日期（0.7）；标题完整 vs 截断；正文长度（社区源）。

## 2. 交叉验证（corroboration）

不做 claim 级 NLP，做**事件聚簇 + 证据根归并**：

### 2.1 事件聚簇 key

```
event_key = (区名, 学校实体, event_type, 学年)
```

- 学校实体用**词典法**抽取：149 校名单 + 全称/简称别名表（已有 aliases 机制）
- `event_type` 已有（报名/派位/摇号/招生简章…）
- 学年从标题/正文正则抽 `20\d{2}`，抽不到归"未知年"（不参与跨年验证）

### 2.2 证据根归并（防"转载当多源"）

家长论坛和媒体的"多源报道"常常是同一条通稿。处理：
- 抽取正文中的**官方 URL**（jw.beijing.gov.cn / yjrx / 区政府域名）作为 `evidence_root`
- 同一 evidence_root 的所有条目算**一个证据**，只计根的 tier
- 无官方链接的媒体/社区条目，各自独立计 0.5/0.3 证据

### 2.3 验证规则（输出仍是离散标签 + 分数）

| 情形 | 结果 |
|---|---|
| 聚簇内出现 T0-T2 证据 | 官方确认（community 条目的 `needs_official_verification` 关闭） |
| ≥2 个独立证据（不同 root）、无冲突 | 多源一致 |
| 仅单一 T4/T5 证据 | 待验证 |
| 聚簇内**数值/日期冲突**（如报名时间 5月6日 vs 5月8日） | 信息冲突，两边降权 ×0.5，列出冲突点 |

分数映射：官方确认 0.9+；多源一致 base + 0.15（上限 0.85）；待验证 = base；冲突 ×0.5。

### 2.4 冲突检测的可计算部分

- **日期比对**：聚簇内正则抽全日期，去重后 >1 个不同日期 → 冲突
- **关键数值比对**：招生人数、班数（`\d+ 个班`/`\d+ 人`）同上
- 不做语义级冲突（超出零依赖能力），冲突标签要写清"检测到的差异是什么"

## 3. 时效性

### 3.1 双轴：招生年度 × 类型化时效衰减

招生信息不是普通新闻——**去年 4 月的政策和今年 4 月的政策内容像但年份错**。研究综述（temporal KG 的 validity 区间思想，García-Durán 2018 / Lacroix 2020）给出的数据模型结论是：**每条信息显式绑定 `policy_year`（招生年度）字段**，而不是靠发布日期隐式推断。

```
policy_year  = 标题年份正则（"20XX年义务教育入学"）校正 > 发布日期推断
year_match   = policy_year == 当前招生年度 ? 1.0 : 0.4   # 往年"仅供参考"
freshness    = 按 content_type 分参数的衰减（HN 幂衰减离散版）
final        = confidence × year_match × freshness
```

关键：**官方政策原文在其年度内不随时间衰减**（freshness 是"内容相对真实世界状态的时效"，Dai & Davison 2010——政策原文年度内永远新鲜），只按 policy_year 切换。这是本看板相对搜索引擎（分钟级 freshness）的本质差异：我们的问题是**年度级有效期**。

类型化衰减参数（依据：Google freshness"按主题分时间尺度"；Vosoughi 2018 社区信息传播快失效也快）：
- 官方政策原文：不衰减，仅年度切换
- 学校通知：半衰期 90 天（学校官网更新随意且滞后）
- 活动通知/报名节点：半衰期 14 天
- 社区帖：半衰期 14 天
- 招生季（4–7 月）所有类型时间项加权 ×2
- 无日期条目：freshness 固定 0.6 并标"时间未证实"

### 3.2 "来源比内容更旧"检测

B2 统一建站平台常见整站重新上线导致老内容带新时间戳：正文年份正则与发布时间戳比对，不一致 → 标"疑似旧文重发"。

### 3.3 过期检测

官方源已有新学年版本、社区仍在传旧版本 → 同 event_key 不同 policy_year 即可判定，旧条目标"疑似过期，官方已更新"。

### 3.4 日期证据优先级

标题内日期 > 正文首段日期 > URL 路径中的 `YYYYMM` > `published_at_hint` > crawled_at（仅兜底）。当前 `parse_spec` 已抓列表页 date，社区源有 hint，够用。

## 4. 用户可见的展示（可解释性）

依据 HCI 文献的三条硬约束：

1. **不给连续分数**（van der Bles 2019：小数点精确度会被误读为准确度）——展示档位/标签，不展示 0.72
2. **标签必须全量打**（Pennycook 2020 implied truth effect：只给低置信度打标签，会让无标签的官方条目被误读为"已验证"）——所有条目一律有标签，官方条目也不能裸奔
3. **徽章旁必须有一句话理由**（van der Bles：数值不确定性要与"为什么"的叙述一起给）

每条信息卡片（NewsGuard Nutrition Label 的精简版）：
```
[标签] 多源一致 · 3 个独立来源 · 2026-10-20
标题……
来源徽章：市教委 ↗ ｜ 朝阳家长帮 ↗ ｜ 北京小升初网 ↗
（冲突时：⚠ 两源报名时间不一致：5月6日 / 5月8日，点击看两方原文）
（往年时：⊘ 2025 年度政策，仅供参考）
```

五个标签从高到低：`官方确认 > 多源一致 > 单一官方 > 待验证 > 信息冲突`，外加 `疑似过期` 覆盖标记。
来源档位徽章三色：官方蓝 / 学校绿 / 社区黄。标签可展开溯源依据（"本条与市教委 10 月 19 日通知指同一政策原文"）——**验证理由本身可点开溯源，这是信任的根**（SIFT 的 Trace to original context）。

注意 Politi & Street (2010) 的区分：**"来源档位"（我们判断的不确定性）与"待官方核验"（事实本身的不确定性）是两个正交标签**，不合并成一个总分。

## 5. 落地改动清单（按依赖顺序）

1. `tools/source_tiers.py`：静态分级表 + `attach_tier(item)`（小，先做）
2. `tools/verifier.py`：事件聚簇、证据根归并、日期/数值冲突检测 → 输出 `docs/verification.json`（可测试的纯函数模块）
3. `tools/build.py`：item 注入 `confidence`/`label`/`label_reason` 字段；社区管线 clean→verify→export 挂接
4. 前端：卡片标签 + 来源徽章 + 冲突提示样式
5. `tests/test_verifier.py`：聚簇、归并、冲突、年度判定的单测

## 6. 明确不做的事

- 不做 LLM claim 抽取（零依赖约束；且不可解释）
- 不做自动事实核查 API 依赖（ClaimReview 覆盖率是英文新闻，对北京招生场景为零）
- 不做信源权重的自动打分模型（Zhou 2021：小来源集上的可信度分类器退化为"站点记忆"；人工配置就是最优解）
- 不做链接图信任传播（PageRank/HITS/TrustRank 需要链接图，政府门户间互不链接，前提不满足——研究综述已判定不适合）
- 不把社区热度当可信度信号（Vosoughi 2018：虚假信息传播反而更快更广，热度与可信度负相关）
- 不把"网页可达性"算进可信度（但失联单独标"来源失联，数据可能过期"——失联是时效性证据）

## 7. 研究综述带来的参数修正记录

| 草案(v0) | 定稿(v1) | 依据 |
|---|---|---|
| 转载检测只靠 evidence_root | evidence_root + 正文 8-gram shingle 重叠 >0.8（维基百科"转载不算多来源"方针） | Wikipedia RS 方针 |
| 活动通知半衰期 7 天 | 14 天；学校通知 90 天；社区帖 14 天 | Google freshness 按主题分尺度 + Vosoughi |
| 政策按年度阶梯衰减 | 政策年度内不衰减，只按 policy_year 切换 | Dai & Davison 2010 |
| 展示分数+标签 | 只展示档位标签，不给数字 | van der Bles 2019 |
| （未考虑） | 标签必须全量打，包括官方条目 | Pennycook 2020 |
| （未考虑） | 来源档位与核验状态是正交双标签 | Politi & Street 2010 |
| 社区源 0.3 权重 | 保持，但可追溯官方原文的帖子上浮一档（TrustRank 弱化版：官方链接 = 信任边） | TrustRank 思想 |

## 8. 落地顺序（下一步动手）

1. `tools/source_tiers.py`：静态分级表 + `attach_tier(item)`
2. `tools/verifier.py`：policy_year 推断 → shingle 转载去重 → 事件聚簇 → 冲突检测 → 状态标签（纯函数，可单测）
3. `build.py` / `community_pipeline.py` 挂接，item 注入 `tier`/`policy_year`/`label`/`label_reason`
4. 前端徽章渲染
5. `tests/test_verifier.py`
